👥 チームTips

Cursor：実際の PR を再生してエージェントをテストする

Agent SDK の agent-sdk github replay は、実在の PR を署名付き webhook のペイロードにしてエージェントに送ります。--dry-run --fixtures-dir fixtures/ を付けると評価用のデータとして保存でき、agent-sdk eval でツール呼び出しや返答の形を確かめられます。

共有用

Cursor の Agent SDK では agent-sdk github replay で実際の PR を webhook として流し込めるので、push を待たずに PR レビュー系のエージェントを試せます。--dry-run --fixtures-dir fixtures/ で評価用データとして保存し、agent-sdk eval で回帰テストにできます。 https://cursor.com/changelog

👥 チームTips

エージェント設計は「1本のループ＋スキルとツールの段階読み込み」から

Anthropic は、サブエージェントに分ける前に、1つのエージェントがスキルとツールの短い説明だけを持ち、必要なときに中身を読み込む形を勧めています。サブエージェントは、評価で独自の文脈が必要と分かったものだけ残すのが基本です。

共有用

Anthropic の記事によると、エージェントは最初からサブエージェントに分けるより、1本のループにスキルとツールを必要なときだけ読み込ませる形が基本とのことです。分けるのは評価で効果が確かめられたものだけにすると、引き継ぎで情報が落ちにくくなります。 https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop

👥 チームTips

Bedrock の Web Search で参照先を信頼できるドメインに絞る

Bedrock の web_search ツールに filters の allowed_domains（最大100件）を指定すると、根拠に使う検索結果を公式ドキュメントなどに限定できます。blocked_domains で除外も可能です（現在は米国リージョンと GovCloud のみ）。

共有用

Amazon Bedrock の Web Search は、web_search ツールの filters に allowed_domains を指定すると、回答の根拠を指定したドメインだけに絞れます（最大100件、blocked_domains で除外も可）。社内向けの調査ボットで公式ドキュメントだけを見せたいときに使えます。 https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-web-search-domain-user-location/

Claude Code：git 管理外の生成ファイルを @ で選べるようにする

v2.1.311 から、@ のファイル選択が .ignore / .rgignore の否定ルールに従うようになりました。.gitignore で除外している生成コード（GraphQL の型など）も、.ignore に !パス を書けば @ で指定できます。

共有用

Claude Code（v2.1.311〜）では、.gitignore で除外しているファイルでも、.ignore に !パス を書けば @ のファイル選択で選べるようになりました。生成された GraphQL の型などをエージェントに読ませたいときに便利です。 https://github.com/anthropics/claude-code/releases/tag/v2.1.311
