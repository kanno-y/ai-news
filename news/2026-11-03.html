Claude API にメッセージスレッド（beta）：2ターン目からは新しいメッセージだけ送る

Messages API に thread パラメータが入り、会話をサーバー側に短時間預けて、以降は新しいメッセージと直前の応答 id だけを送ればよくなりました。リクエストが小さくなり、会話が伸びても最初のトークンまでの時間が安定します（スレッドは最後のリクエストから5分で期限切れ）。

💡 ヘッダー anthropic-beta: message-threads-2026-08-12 を付け、初回は "thread": {"type": "create"}、次から {"type": "continue", "previous_message_id": …}。SDK の beta tool runner は既定でスレッドを使い、スレッドは ZDR 対象外なので、ZDR が必要な処理では thread: false を確認。

Vercel MCP、事前登録なしの MCP クライアントも接続できるように

Client ID Metadata Documents（CIMD）に対応し、どの MCP クライアントも Vercel の審査なしで接続を申請できるようになりました。ログインと接続ごとの承認は引き続き必要です。

💡 承認画面ではクライアント名だけでなく、メタデータを配信しているホスト名（例「Claude Code by claude.ai」）を見てから Allow Access を押す。CIMD クライアントには verified バッジは付きません。

👥 チームTips

pnpm：公開から1日たっていないバージョンは入れない（minimumReleaseAge）

pnpm-workspace.yaml に minimumReleaseAge: 1440（単位は分）を書くと、間接依存も含めて公開から1日未満のバージョンが入らなくなります。すぐに取り下げられる乗っ取り版を踏みにくくなり、急ぎのパッケージは minimumReleaseAgeExclude で例外にできます。

共有用

pnpm-workspace.yaml に minimumReleaseAge: 1440 を書くと、公開から1日たっていないパッケージは間接依存も含めて入らなくなります。すぐ取り下げられる乗っ取り版を避けやすくなり、例外は minimumReleaseAgeExclude に書けます。https://pnpm.io/settings/dependency-resolution

👥 チームTips

Next.js：ログや計測は after() でレスポンスのあとに回す

next/server の after()（v15.1 で安定版）に渡した処理は、レスポンスを返したあとに動くので、ログや分析で応答を遅らせません。エラーや redirect のときも実行されます。Server Component では cookies() や headers() をコールバックの中で呼ぶとエラーになるので、先に読んで値を渡します。

共有用

Next.js 15.1 以降は next/server の after() で、ログや分析をレスポンス送信後に回せます。Server Component では cookies() や headers() を先に読んで値を渡してください（コールバックの中で呼ぶとエラーになります）。https://nextjs.org/docs/app/api-reference/functions/after

👥 チームTips

Google Cloud：Gemini API や Cloud Run に月の上限額（spend cap）を付ける

10月に正式版になった spend cap 付きの予算は、1プロジェクト・1サービス単位で、見積もり費用が上限を超えるとその月の残りは新しいリクエストを止め、翌月に自動で再開します。リソースは消えません。止まるまでに少し時間差があり、その間の超過分は請求されます。

共有用

Google Cloud の予算で spend cap を設定すると、Gemini API や Cloud Run の見積もり費用が上限を超えた時点で、その月の残りは止まります（リソースは消えません）。止まるまでの超過分は請求されますが、キー漏れやループ暴走の保険になります。https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps
