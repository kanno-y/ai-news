Claude Code v2.1.314〜316：Opus 4.8 の fast mode が11月30日で終了

Opus 4.8 の fast mode は10月30日に非推奨になり、11月30日以降に speed: "fast" を付けると、通常速度に戻らずエラーになります。同じリリースで、作業フォルダの外への書き込みを止める設定も入りました。

💡 claude-opus-4-8 と speed: "fast" の組み合わせがスクリプトや設定に残っていないか探し、Opus 5.5 に移します。claude update のあと、settings.json の permissions に "blockWritesOutsideWorkingDirectories": true を入れると、Write・Edit・NotebookEdit が作業フォルダの外のパスを拒否します。

Vercel の Data Cache が Runtime Cache に統合、読み書きが課金対象に

Next.js の fetch キャッシュと unstable_cache がコード変更なしで Runtime Cache に移り、これまで無料だった読み書きに料金がかかります。Hobby は11月29日に移行し、Pro には移行日が個別に通知されます。

💡 移行前に Observability で Data Cache の読み書き量を確認します。多ければ Runtime Cache ダッシュボードの「Optimize with Vercel Agent」か最適化ガイドで減らします。早めに切り替えたい場合は CDN settings から移行できます。

Claude の Max 20x が「Ultra」に、確認済みアカウントは5時間制限なし

Claude Code：チームで使う MCP は --scope project で共有

claude mcp add --transport http <名前> <URL> --scope project で追加すると、プロジェクト直下の .mcp.json に書かれ、コミットすれば全員が同じ MCP サーバーを使えます。API キーは ${API_KEY} のように環境変数で書けば、秘密をコミットせずに済みます。

共有用

チームで使う MCP サーバーは、claude mcp add に --scope project を付けると .mcp.json に保存され、コミットするだけで全員にそろいます。API キーは ${API_KEY} の形で書けば秘密を入れずに済みます。https://code.claude.com/docs/en/mcp

👥 チームTips

Cursor：push する前に /review-bugbot でレビュー

エージェントで /review-bugbot を実行すると、ブランチの変更を Bugbot がその場でレビューします。同じ差分で PR を作ると、GitHub 側の Bugbot は重ねてレビューしません。Cursor 3.7 以降と Cursor CLI で使えます。

共有用

Cursor で /review-bugbot を実行すると、push 前に Bugbot のレビューを受けられます。同じ差分で PR を出すと GitHub 側では二重にレビューされません。https://cursor.com/docs/bugbot

👥 チームTips

Playwright：--only-changed と --last-failed でテストを絞る

npx playwright test --only-changed はコミットしていない変更に関係するテストファイルだけを、--only-changed=main なら main との差分だけを実行します。--last-failed は前回失敗したテストだけを再実行します。

共有用

Playwright の E2E を毎回全部回さず、npx playwright test --only-changed で変更したテストだけ、--last-failed で前回落ちたものだけを実行できます。https://playwright.dev/docs/test-cli

👥 チームTips

Grok API：急ぎのリクエストだけ service_tier: "priority"

Chat Completions と Responses API でリクエストごとに service_tier: "priority" を付けると、優先して処理されます。実際に使われた tier はレスポンスの service_tier でわかり、priority の料金は使ったときだけかかります。

共有用

Grok API で応答を急ぎたいリクエストだけ service_tier: "priority" を付けると優先処理されます。実際の tier はレスポンスの service_tier で確認でき、料金は使ったときだけです。https://docs.x.ai/developers/advanced-api-usage/priority-processing
