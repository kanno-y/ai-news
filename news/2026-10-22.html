Cursor のローカルエージェントを iPhone から見て返信する

Cursor の iOS アプリにサインインし、デスクトップでペアリングを承認すると、手元の PC で動くローカルエージェントの様子を見たりメッセージを送ったりできます。離席中に止まらないよう、デスクトップ設定の Remote Control にある「Keep this computer awake」をオンに（電源接続・蓋を開けたままが条件。Enterprise は管理者が有効化）。

共有用

Cursor のローカルエージェントは iOS アプリから様子を見て返信できます。席を外す前に Cursor の設定の Remote Control で「Keep this computer awake」をオンにしておくと、スリープで止まりません（電源につないで蓋は開けたまま）。 https://cursor.com/changelog

👥 チームTips

CloudWatch アラームの通知にタグを載せて、Lambda で振り分ける

アラームごとに設定をオンにすると、SNS・Lambda・EventBridge に送られるメッセージにアラームのタグが入り、通知のたびに ListTagsForResource を呼ばずにチームや環境で振り分けられます。既定はオフで、全タグ・指定キーのみ・指定キー以外から選べます。

共有用

CloudWatch アラームの通知（SNS・Lambda・EventBridge）にアラームのタグを含められるようになりました。アラームごとにオンにすれば、通知を受ける Lambda で ListTagsForResource を呼ばずにタグで振り分けられます。 https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-cloudwatch-tags-on-alarm-actions-payload

AGENTS.md に「実装をなぞる単体テストはコミットしない」と書く

共有用

👥 チームTips

Claude API のキャッシュが効かない理由を diagnostics で聞く

Messages リクエストに diagnostics オブジェクトを付けて前のターンの previous_message_id を渡すと、プロンプトキャッシュが前回とどこでずれたかを cache_miss_reason で返してくれます。毎ターン付け、最初のターンは null にします。ベータヘッダーは不要です。

共有用

Claude API でプロンプトキャッシュが効かないときは、リクエストに diagnostics（previous_message_id）を付けると、ずれた理由を cache_miss_reason で返してくれます。ベータヘッダーなしで使えます。 https://docs.claude.com/en/release-notes/api
