👉 やってみる：npm install next@15.5.29 → rg -n "runtime = 'edge'" app src で Edge ルートを洗い出し、その中の NextResponse.cookies.set と return fetch( のそのまま返しを確認。Node ランタイムや cookies().set() は影響なし。

🧪 実践テクニック

PostToolUse フックで「テスト失敗」を Claude に届けるには exit 2

編集後にテストや lint を走らせるフックは、普通に失敗（exit 1）すると Claude には見えず、そのまま作業が続きます。PostToolUse で exit 2 にすると stderr が Claude に渡り、直してから完了を報告するようになります。

👉 やってみる：npm run lint || { echo "lint failed" >&2; exit 2; } のような小さなラッパーを PostToolUse に登録し、型チェックと lint だけにする。重い全テストは Stop フックに回す（exit 2 で終了をやり直させられる）。

Vercel CLI：vercel doctor --json で環境の問題をエージェントに調べさせる

共有用

vercel doctor で、Vercel CLI のバージョン・ログイン・プロジェクトのリンク・vercel.json・障害情報をまとめて確認できます。--json を付けると結果を機械で読めて途中で入力も求めないので、デプロイがうまくいかないときはエージェントに先に実行させるのがおすすめです。https://vercel.com/changelog/vercel-cli-now-diagnoses-setup-problems-with-vercel-doctor

Vercel のプロジェクト設定を vercel.toml で書けるように（コメントOK）

vercel.json と同じ設定を TOML で書けるので、リダイレクトやヘッダーの理由をコメントで残せます。vercel.toml・vercel.json・vercel.ts はどれか1つだけ置きます。

共有用

Vercel のプロジェクト設定が vercel.toml でも書けるようになりました。コメントが書けるので、リダイレクトやヘッダーの理由を残しておけます。vercel.json / vercel.ts と併用はできないので、移すときは1つにまとめてください。https://vercel.com/changelog/projects-can-now-be-configured-with-vercel-toml

Claude Code：整理は /simplify、バグ探しは /code-review と使い分ける

/simplify は4つのレビューエージェントが並列で、既存ヘルパーの再利用・簡素化・効率・抽象度を見て直しますが、正しさのバグは見ません。バグを探すなら /code-review を使います。

共有用

Claude Code の /simplify は、変更したコードを4つのエージェントが並列で見て、既存ヘルパーの再利用や簡素化などの整理をしてくれます。ただバグは見ないので、PR 前は /simplify で整えてから /code-review でバグを確認する順番がおすすめです。https://code.claude.com/docs/en/commands
