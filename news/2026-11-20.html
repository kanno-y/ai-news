Claude Code v2.1.327〜329：保存済みのスケジュールタスクは登録し直しに。auto mode は pnpm dlx などの許可ルールを無視

11月20日 7:14ごろ（日本時間）の v2.1.329 から、以前のバージョンで保存したスケジュールタスクの多くは、新しくサインインしたセッションでは登録し直しが必要になりました（そのセッション自身を --resume した場合は動きます）。v2.1.327 では、auto mode が Bash(pnpm dlx *) のような「任意のパッケージを実行する」許可ルールを無視して安全チェックに判断させるようになり、無人で回している作業が確認待ちや拒否で止まることがあります。

👉 やってみる：上げてから、残っているタスクと、効かなくなる許可ルールを探す。
claude update && claude --version && rg -n 'dlx|npx|bunx|npm exec|uvx' ~/.claude/settings.json .claude/settings*.json 2>/dev/null
定期実行させていたセッションで /tasks を開き、そのセッションのスケジュールタスクが載っているかを見る（v2.1.329 からスケジュールタスクと /loop も載ります）。新しいセッションで使うものは登録し直す。pnpm dlx 系を許可で通していた作業は、package.json の scripts にして Bash(pnpm run lint) のように個別に許可する。

🧭 エージェント活用スキル

🧭 エージェント活用スキル

「終わりました」の前に検証を必ず通させる：Stop フックで verify を走らせ、失敗なら作業に戻す

lint・型・テストを1つの verify にまとめ、Stop フックで実行して失敗したら exit 2 を返すと、Claude は止まらずに直しに戻ります（Stop フックの exit 2 は「止まらせない」動作）。フックには、すでにフックで続行中かを示す stop_hook_active が渡されるので、直らない条件で止め続けないよう公式ドキュメントも確認を勧めています。

👉 やってみる：package.json に1本にまとめる（ビルドは重いので CI 側に任せる）。
"verify": "eslint . && tsc --noEmit && vitest run"
実装用のセッションだけで効くよう .claude/settings.local.json に入れる。
{"hooks":{"Stop":[{"hooks":[{"type":"command","command":"npm run verify --silent || (echo 'verify failed: 直してから終えて' >&2; exit 2)"}]}]}}
テスト名を受入条件に合わせておく（例：test('AC-2 未登録コードはエラーを出して何も変えない')）と、落ちたときにどの条件が未達かすぐ分かります。

🧭 エージェント活用スキル

エージェントの「無理そう」を鵜呑みにしない：小さく1つ試させてから見積もり直させる

Anthropic が1,000体のエージェントで行った実験では、序盤に helper たちが60個の命題のうち47個を「予算内では無理」と判定しましたが、チームは最終的にそのほとんどを証明しました。記事は「エージェントは難しい問題を早く諦め、難しさを見誤りがち」とし、要所での人の後押しが有効だとまとめています。

👉 やってみる：エージェントが「範囲が大きすぎる」「この方針では難しい」と言ってきたら、手を止めさせる前にこう返す。
「難しい」と判断した根拠を3行で書いて。そのうえで、一番小さく切り出せる部分を1つだけ実際に実装してテストを通し、かかった手数と分かったことから、残りの見積もりを出し直して。それでも無理なら、どこで詰まったかを具体的に（ファイル・エラー文）示して。
大きいタスクは「1つで手に余るなら子タスクに分けて書き足してよい」と最初に伝えておくと、諦める代わりに分解してくれます。

🔒 セキュリティ

🔒 セキュリティ

AWS 公式 MCP サーバーの脆弱性修正が続く：入れているもののバージョンを確かめ、「読み取り専用」の注釈を信じて自動承認しない

awslabs/mcp で11月に入って4件の修正が公開され、身近なのは次の3件です。AWS API MCP Server（1.5.1 で修正、high）は、大文字が続く操作名で独自ポリシーの denyList・elicitList が効かず、拒否したはずの API を実行できる問題。Serverless MCP Server（0.2.1 で修正）はパス操作で範囲外の JSON を読み書きでき、Pricing MCP Server（1.0.31 で修正）はファイルを書くツールが「読み取り専用」と注釈されていたため、読み取り専用ツールを自動承認するクライアントでは確認なしに実行され得ました。

👉 やってみる：設定に awslabs のサーバーがあるか探す。
rg -n 'awslabs\.[a-z0-9-]+' ~/.claude.json .mcp.json ~/.cursor/mcp.json .cursor/mcp.json 2>/dev/null
古い版を固定していたら awslabs.aws-api-mcp-server@1.5.1、awslabs.aws-serverless-mcp-server@0.2.1、awslabs.aws-pricing-mcp-server@1.0.31 以上に上げる（awslabs.cost-analysis-mcp-server は修正版が出ないので Pricing に移行）。あわせて、MCP サーバーに渡す AWS_PROFILE を読み取り専用のロールにして、サーバー側のポリシー設定だけに頼らない。

Claude Code の /code-review で、ブランチ全体を「直すべき指摘」だけに絞ってレビューする

v2.1.328 で /code-review はバグと CLAUDE.md 違反だけを報告し、各指摘に Important（重要）・Pre-existing（元からある問題）・Nit（細かい点）の印と修正案が付くようになりました。v2.1.329 では引数なしでブランチ全体を既定ブランチと比べてレビューし、複数コミットで差分を見失う不具合も直っています。

👉 やってみる：PR を出す前に、作業ブランチで引数なしで実行してから、こう続ける。
/code-review
いまのレビュー結果のうち Important だけを直して、直すたびに npm run verify を通して。Pre-existing は今回は直さず、ファイル・行・内容を一覧にして別タスク用にまとめて。Nit は無視でいい。
PR 番号を渡すときは gh が使える状態で（gh pr diff が失敗するとレビューせずに止まるようになりました）。

「設定したのに効かない」ときは、まず /status で壊れた設定の一覧を見る

👥 チームTips

止めるためのフックには "onFailure": "block" を付けて、壊れたときに全部通さない

Claude Code のフックは、多くのイベントで失敗やタイムアウトしても操作をそのまま進めます。パスの書き間違いやスクリプトのクラッシュでガードが素通りになるので、command・http・mcp_tool のフックに "onFailure": "block" を付けると、失敗時は止める側に倒れます（mcp_tool は v2.1.328 以降）。

共有用

Claude Code のフックは、失敗やタイムアウトしても多くの場合そのまま操作が進むので、危ないコマンドを止めるためのフックには "onFailure": "block" を付けておくと安心です。スクリプトのパスを間違えたときも素通りにならず、止まってくれます。https://code.claude.com/docs/en/hooks#block-the-action-when-a-hook-fails
