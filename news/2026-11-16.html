Claude Code v2.1.325：サンドボックス内の Bash も既定で許可を聞くように。無人で回している設定を見直す

11月14日 5:40ごろ（日本時間）のリリースで、サンドボックス内の Bash コマンドが通常の許可フローに従うようになりました（これまでどおり聞かずに実行させるには sandbox.autoAllowBashIfSandboxed: true）。あわせて、スケジュールタスクと /loop は allowed-tools やフックを宣言したスキルの実行前に確認するようになり、プロジェクト外の未信頼リポジトリでの読み取り専用 git も確認が出ます。zstd 圧縮レスポンスのデコードに関するセキュリティ修正も入っています。

👉 やってみる：まず上げて、サンドボックス頼みで無確認にしていた設定があるかを探す。
claude update && claude --version && rg -n 'autoAllowBashIfSandboxed|"sandbox"|Skill\(' ~/.claude/settings.json .claude/settings*.json
これまでどおり回したいなら、ユーザー設定（~/.claude/settings.json）に次を足す。/loop で回すスキルは名前で許可に入れる。
{ "sandbox": { "enabled": true, "autoAllowBashIfSandboxed": true }, "permissions": { "allow": ["Skill(スキル名)"] } }

「最小限で直して」をやめる：その場しのぎの修正はエージェントが真似して広がる

pstack の作者 Lauren Tan（poteto）さんが、エージェントに「一番小さい・早い修正」を頼むと、その場しのぎのパターンを次のエージェントが真似して、気づくとコードベース中に広がると指摘しました。返信でも「自分が思う直し方のヒントを先に与えるのは逆効果」という声が出ています。

👉 やってみる：ルールファイル（CLAUDE.md / .cursor/rules）に1段落足す。
修正は根本原因を特定してから行う。暫定の回避策を入れる場合は TODO と理由を書き、同じ形を他の箇所に広げない。新しいコードは既存の同種コードのパターンに合わせる。
バグ修正の依頼文は「早く・小さく」ではなく、こう頼む。
このバグの根本原因を先に説明して。直し方は私の推測に合わせなくていい。同じ原因の箇所がほかにないか rg で探して一覧にし、再現テストを先に赤にしてから修正して。

Claude Code の auto memory を「索引」として小さく保ち、古いメモを定期的に捨てる

Anthropic の「The components of agent memory」は、メモを書くことは「未来にも必要になる」という予測であり、間違ったメモは毎セッションに持ち込まれると説明し、アイドル時に記録を見直して整理する「dreaming」を紹介しています。Claude Code の auto memory も、起動時に読まれるのは MEMORY.md の先頭200行か25KBまでで、それを超えた分は落ちます。

👉 やってみる：大きさを見てから、Claude に棚卸しさせる。
wc -lc ~/.claude/projects/*/memory/MEMORY.md
このリポジトリの auto memory（~/.claude/projects/<project>/memory/）を見直して。MEMORY.md は1行1項目の索引にし、詳細はトピックファイルへ移す。今のコードや設定と食い違うメモ、一度きりの事情のメモは削除候補として一覧にして、私が OK したものだけ消して。

Cursor の事故報告から学ぶ：エージェントのチャットやサポートに貼った鍵は「残る」前提で扱う

Cursor が11月13日に公開した続報によると、委託先 Fireworks に渡した鍵の流出から、Privacy Mode でないセッションのエージェントのトレース（主に2025年分）に残っていた未マスクの認証情報が使われ、サポートに送られた認証情報にも到達しました。10月29日に出た Claude Code 拡張の偽版（2.1.312・2.1.313）もこの流れで置かれたものです。Privacy Mode 利用者のプロンプトとコードは対象外とされています。

👉 やってみる：Cursor の設定で Privacy Mode が有効か（仕事ならチームで強制されているか）を見て、手元のエージェントの記録に鍵が残っていないかを探す。見つかった鍵はローテーションする。
rg -l -e 'AKIA[0-9A-Z]{16}' -e 'sk-[A-Za-z0-9_-]{20,}' -e 'ghp_[A-Za-z0-9]{36}' -e 'xox[bp]-' ~/.claude/projects ~/.cursor 2>/dev/null | head -20
今後はチャットに鍵を貼らず、.env の値を読むよう指示する。Cursor からの影響の連絡（メール・アプリ内通知）が届いていないかも見ておく。届いていなければトレースは対象外と書かれています。

provenance 付きでも安心しない：依存を上げる前に package.json の scripts 差分を見る

11月9日の @ethersphere/bee-js 13.3.0 は、リリース用ボットの認証情報を奪った攻撃者が正規の SLSA provenance 付きで公開したもので、"prepare" を "postinstall" に1行変えるだけで利用者の npm install 時に実行させていました。npm からは75分で消えましたが、同じ攻撃者が出した Swarm Desktop の GitHub リリースはその後も約8時間残りました。

👉 やってみる：依存更新の PR や手動アップデートの前に、公開物どうしの差分で install 系スクリプトの追加・変更を見る。
npm diff --diff=パッケージ名@旧版 --diff=パッケージ名@新版 -- package.json | rg -n 'preinstall|"install"|postinstall|prepare'
手元とCIの npm がインストールスクリプトをどう扱うかも見る（記事によると npm 12・pnpm 10・Bun は依存のスクリプトを既定でブロック、npm 11 以前は実行）。
npm --version && npm config get ignore-scripts && pnpm --version 2>/dev/null

Claude Code の Code Mode（実験的）：複数ファイルの一括変更や大量検索を1ステップで回す

v2.1.323 から、Claude がツール呼び出しを JavaScript で書いてまとめて実行する Code Mode を試せます。同じ変更が多くのファイルにまたがる作業や、結果を絞ってから読む検索に向いていて、各ツール呼び出しは deny/ask ルールと PreToolUse フックを通ります。ただし -p・VS Code パネル・Bedrock では使えず、auto mode の分類器はツール呼び出しごとではなくコード全体を見る、Code Mode のセッションは Code Mode をオンにしないと再開できない、といった制限があります。

👉 やってみる：個人の学習用リポジトリで、ターミナルから試す（Opus 5.5・Sonnet 5.5 などの対応モデルが必要）。
CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude
このプロジェクトの Markdown をすべて読んで、存在しないローカルファイルを指すリンクを一覧にして。
終わったら Ctrl+O で Claude が書いたコードを開き、どの呼び出しをまとめたかを見る。

Orca v1.4.259：終わったワークスペースを自動で片付け、サブエージェントを1つずつ追う

11月15日 6:20ごろ（日本時間）のリリースです。Settings → Workspace Cleanup で条件に合うワークスペースを確認して自動で片付けられ、プロジェクトごとにルールを持てます。サブエージェントのタスク・途中経過・最終回答を専用ビューで開いて、元の会話に戻れるようになりました。クリーンアップは既定でオフで、有効にすると確認後数秒で削除されることがあり、アーカイブはできません。

👉 やってみる：有効にする前に、削除プレビューに出たワークスペースに未コミット・未 push の作業がないかを一気に確かめる。
git worktree list --porcelain | awk '/^worktree/{print $2}' | while read d; do echo "== $d"; git -C "$d" status -s; git -C "$d" log --oneline @{u}.. 2>/dev/null; done
何も出ないものだけ対象に残してルールを有効にする。並列で走らせたときは、サブエージェントの専用ビューで最終回答だけ先に読む。

👥 チームTips

Bash の deny ルールは「文字列一致」。本当に止めたいものはサンドボックスで

Claude Code のドキュメントは、Bash のルールはコマンドの文字列で照合するため、ルールに当たらない別の書き方で同じことを実行されうると注意しています。文字列に頼らない制限にはサンドボックスを使うよう案内しています。

共有用

Claude Code の Bash の deny ルールはコマンド文字列で照合するので、別の書き方ですり抜けることがあるそうです。本当に止めたい操作（本番への接続など）は /sandbox で守るのがおすすめです。https://code.claude.com/docs/en/code-mode

👥 チームTips

MCP の書き込み系ツールをワイルドカードで常時許可しない

11月14日公開の論文「Log-To-Leak」は、ツール説明に仕込んだ指示で、正規の処理が終わった後に攻撃者のツールへ「ログ」として内容を送らせる攻撃を検証し、タスクは普通に完了したまま情報が漏れることを示しました。対策としてホスト側で後続のツール呼び出しを許可制にすることを挙げています。

共有用

MCP のツール説明に仕込まれた指示で、作業が終わった後に「ログ送信」として内容を外へ送らせる攻撃が報告されています。permissions.allow に mcp__xxx__* のようなワイルドカードで書き込み系ツールを入れていないか、一度見直しておくと安心です。https://dl.acm.org/doi/10.1145/3847320.3847399

Aurora PostgreSQL の express configuration を CloudFormation で1行で作る

AWS::RDS::DBCluster に createOnly プロパティ withExpressConfiguration が加わり、クラスターとプライマリインスタンスを1つの宣言で作れるようになりました。インスタンスを別リソースとして書かなくてよいので、検証用の DB をテンプレートで手早く用意できます。
