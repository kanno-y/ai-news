🧭 エージェント活用スキル

「絶対に守る」ルールは CLAUDE.md から外し、hook と deny ルールに移す

同じガイドは、CLAUDE.md・プロンプト・スキルは Claude が判断する「非決定的」な指示で、hook・deny ルール・managed settings は Claude Code が毎回必ず適用する「決定的」な指示だと整理しています。IMPORTANT を足しても守られない行は hook 向き、逆に好みでしかない hook は消してよい、という線引きです。deny は auto モードや bypassPermissions でも効きます。

👉 やってみる：CLAUDE.md の「絶対」「必ず」「禁止」を rg -n "絶対|必ず|禁止|IMPORTANT|NEVER" CLAUDE.md .claude/ で洗い出し、例外がないものだけ .claude/settings.json に移す。
{"permissions":{"deny":["Read(./.env)","Read(./.env.local)","Read(./secrets/**)"]}}
移したら「.env の中身を教えて」と頼んで、cat .env でも拒否されるか確かめる（スクリプトから開く場合は防げないので /sandbox も併用）。

🔒 セキュリティ

デスクトップアプリが勝手に足したプラグインや SessionStart フックを見つけて外す

Postman デスクトップ版（12.33.4 など）が、起動時の自動処理で Claude Code・Codex にプラグインを入れ、Cursor にも同じ起動時の指示が入っていたと GitHub の issue で報告されています。API の作業では Postman のスキルを使うよう指示する SessionStart フックや、リモート MCP、~/.local/bin の CLI も追加されていました。Postman は「導入を楽にするためだった」として、オプトインを分かりやすくすると回答しています。

👉 やってみる：Postman を使っていなくても、ほかのアプリが同じことをしていないか見ておく。
jq '{enabledPlugins, hooks}' ~/.claude/settings.json; cat ~/.claude/plugins/installed_plugins.json; rg -il postman ~/.claude ~/.cursor 2>/dev/null; ls -la ~/.local/bin
見覚えのないプラグインやフックがあれば、出どころを確認してから削除。Postman の場合は報告者によると Help → Postman CLI and Plugins → Uninstall Postman Coding Agent Plugin で外せますが、取り残しがないか同じコマンドで再確認する。
GitHub：postman-app-support #14370 ↗
🔒 セキュリティ

エージェントが「学習データで覚えた古い MCP サーバー」を入れていないか点検する

Glow Labs の調査（MCPhantom）で、エージェントに「GitHub の MCP を入れて」と頼むと、アーカイブ済みで今後修正されない @modelcontextprotocol の旧リファレンスサーバーを選ぶ例が見つかりました。Puppeteer サーバーにはプロンプトインジェクション経由で任意のコマンドを実行できる脆弱性があり、修正は出ないとされています。

👉 やってみる：MCP 設定から旧サーバーを探し、各サービスの提供元が出している公式サーバーに置き換える。
rg -n "@modelcontextprotocol/server-" ~/.claude.json ~/.cursor/mcp.json .mcp.json .cursor/mcp.json 2>/dev/null
出てきた名前を servers-archived の一覧と見比べる。再発防止に AGENTS.md へ「MCP サーバーを追加するときは、そのサービスの公式サーバーを使い、追加前に私に確認する」と1行足す。

Claude Code v2.1.318：claude.ai ログインの期限切れを、止まる前に知る

claude auth status に保存済みログインの期限（loginExpiresAt）が出るようになり、claude -p の JSON 結果にも credential_expires_at が入りました。テキスト出力では期限の10日前から stderr に1行の警告が出ます。夜間や定期実行のジョブが「Not logged in」で止まるのを防げます。

👉 やってみる：claude update のあと、期限を確認する。
claude auth status
定期実行のスクリプトでは claude -p --output-format json の結果から credential_expires_at を読み、近ければ自分に通知する処理を足す。切れていたら claude auth login か claude setup-token でやり直す。

🛠 ツール活用

Claude Code の worktree に .env を自動でコピーして、並列作業をすぐ始める

worktree は新しいチェックアウトなので、.env など gitignore したファイルがなく、そのままでは動きません。リポジトリ直下に .worktreeinclude（書き方は .gitignore と同じ）を置くと、Claude Code が worktree を作るたびにそのファイルをコピーします。node_modules のような大きいものはコピーされるので入れない方がよいとされています。

👉 やってみる：個人用のリポジトリで作成し、claude -w feature-test で worktree のセッションを開いて .env があるか確認する。
printf '.env\n.env.local\n' > .worktreeinclude
依存のインストールは CLAUDE.md に「新しい worktree では最初に pnpm install」と書いておく。

👥 チームTips

clone したリポジトリは、開く前にエージェント用のフック設定を見る

npm ワーム「testmetest」では、乗っ取られた GitHub リポジトリに Claude Code の SessionStart フックや Cursor の MCP 設定などが仕込まれ、ツールで開くだけで隠しファイルが実行される作りでした。.claude/settings.json・.cursor/mcp.json・.cursor/rules/・.vscode/tasks.json を先に読むと防げます。

共有用

外部のリポジトリを clone したら、Claude Code や Cursor で開く前に .claude/settings.json、.cursor/mcp.json、.cursor/rules/、.vscode/tasks.json に見覚えのないフックやコマンドがないか見てみてください。testmetest という npm ワームでは、こうした設定に仕込んだフックで、開いただけで不正なファイルが実行される作りになっていたそうです。https://research.jfrog.com/post/beyond-testmetest-42-hijacked-github-repos/

👥 チームTips

副作用のあるスキルは disable-model-invocation: true で手動起動だけにする

リリースのように実際に何かを動かすスキルは、SKILL.md のフロントマターにこの1行を足すと、Claude が自分の判断で始めることがなくなり、/release のように人が打ったときだけ動きます。

共有用

Claude Code のスキルで、リリースやデプロイのように実際に何かを動かすものは、SKILL.md のフロントマターに disable-model-invocation: true を足しておくと安心です。Claude が勝手に始めなくなり、/スキル名 と打ったときだけ動くようになります。https://code.claude.com/docs/en/best-practices

👥 チームTips

2回直してもダメなら、3回目は言わずに /clear して書き直す

同じ指摘を2回しても直らない会話には、失敗した試みが2つ残っていて、Claude はそれを読み続けます。/clear して、わかったことを入れた新しいプロンプトを1つ書く方が、ほぼ毎回うまくいくと公式ガイドに書かれています。

共有用

Claude Code で同じことを2回直してもうまくいかないときは、3回目の指摘を足すより /clear して、わかったことを盛り込んだプロンプトを1つ書き直す方がうまくいくそうです。会話に失敗した試みが残っていると、それを読み続けてしまうためです。https://code.claude.com/docs/en/best-practices
