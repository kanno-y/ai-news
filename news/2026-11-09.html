🛠 ツール活用要確認

Claude Code v2.1.319：テレメトリ／フィーチャーフラグを切った auto mode は、サーバー確認できない呼び出しが「確認」か「拒否」になる

テレメトリまたはフィーチャーフラグを切っている環境（LLM ゲートウェイ経由を含む）では、auto mode が内蔵の分類器に切り替わらず、サーバー側で確認できない呼び出しを確認または拒否します。従来の動きに戻すには CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定します（Bedrock・Vertex・Foundry は変更なし）。

👉 やってみる：自分の環境が該当するかを探す。
rg -n "TELEMETRY|FEATURE_FLAGS|AUTO_MODE|ANTHROPIC_BASE_URL" ~/.claude/settings.json .claude/settings*.json; env | rg "CLAUDE_CODE|TELEMETRY|ANTHROPIC_BASE_URL"
該当して auto mode を使っているなら、claude update のあとに小さな作業を1つ任せ、確認や拒否が増えていないかを見る。増えたら従来動作に戻す変数を試すか、設定を見直す。該当しなければ対応は不要。

🛠 ツール活用要確認

Orca v1.4.252：macOS 13.4 以上が必須に、ペアリングコードは期限つきに

11月7日のリリースで、Orca の最低 macOS が 12 から 13.4 になりました（古い Mac は最後の対応版にとどまります）。未使用のペアリングコードは、スマホ用 QR が10分、別コンピュータ用リンクが60分で失効し、ローカルのブラウザ制御プロキシはセッションごとのトークンが必要になります。

👉 やってみる：更新前に次を確認する。
sw_vers -productVersion
13.4 未満なら、macOS 13.7 に上げれば更新を受け続けられます。スマホやほかの PC をペアリングし直す予定があるなら、コードを発行したらすぐ使う。

🧭 エージェント活用スキル

🧭 エージェント活用スキル

「できた」を信じず、アプリを動かして確かめる verifier サブエージェントを作る

Claude 公式の教材は、並列セッションは別ファイルを触る作業だけに分け、まず2〜3本から始めるよう勧めています。そのうえで、変更した動作を実際に動かして確かめるサブエージェントを .claude/agents/ に置くと、完了報告の前に検証が入ります。

👉 やってみる：次のファイルを置き、実装を頼んだあとに呼び出す。
mkdir -p .claude/agents && cat > .claude/agents/verifier.md <<'EOF' --- name: verifier description: Runs the app and checks the change works before the session reports done tools: Read, Grep, Glob, Bash --- Start the app and run the relevant tests (e.g. pnpm vitest run path/to/file.test.ts). Exercise the changed behavior and report evidence (commands and output). Report only what does not match the request. EOF
次の機能を頼むときに「完了前に verifier サブエージェントで確認して」と添える。別ファイルを触る作業が2つあるなら claude --worktree feature-a と claude --worktree feature-b で並べ、レビューが追いつく本数までにする。

🔒 セキュリティ

🔒 セキュリティ

Issue を読む bot には秘密も書き込み権限も渡さない：投稿者を確認し、ゲートはモデルに決めさせない

Radware が約1.45億件の GitHub の Issue・PR などを調べ、人には見えずエージェントだけが読める隠しテキストで AI を狙った攻撃（47件）の半数超が、メンテナー自身のトリアージ・レビュー・CI の bot 向けだったと報告しています。トークンを盗ませる指示も実在しました。

👉 やってみる：エージェントを GitHub Actions で動かしているリポジトリで次を点検する。
rg -n "permissions:|GITHUB_TOKEN|secrets\.|issues:|issue_comment|pull_request_target" .github/workflows
(1) Issue やコメントで起動するジョブの permissions: を、読み取りとラベル付けなど必要最小限に明示する。(2) そのジョブにシークレットやクラウド認証情報を渡さない。(3) 「許可」の判定は、モデルの出力ではなく、モデルが書き換えられないチェックにする。(4) コメントのマーカーに従う処理は、投稿者の author_association を確認する。

🛠 ツール活用

Claude Code：permissions.denyInsteadOfPrompting で、確認待ちで止まらず「拒否して先へ」進める

v2.1.319 で追加された設定で、許可の確認待ちになる呼び出しを拒否して、そのターンを続けます（ターミナルのセッション、サブエージェント、チームメイトが対象）。夜間の長い作業が確認待ちで止まりにくくなります。同じ版で、MCP サーバーがタスクとして走らせた呼び出しは、すぐバックグラウンドに回るようになりました。

👉 やってみる：実験用のリポジトリで .claude/settings.local.json に次を入れる。
{"permissions":{"denyInsteadOfPrompting":true}}
claude update のあと、許可していない操作を含む小さな作業（例：未許可のコマンドを使うテスト修正）を頼み、拒否されて作業が続くかを見る。拒否された操作は、必要なら permissions.allow に足す。MCP の待機を従来どおりにしたいときは CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を設定する。

👥 チームTips

Claude Code：大きな機械的変更は /batch で worktree 分離のサブエージェントに分ける

/batch は1つの大きな変更を 5〜30 の worktree 分離サブエージェントに分けるスキルです。同じ種類の置き換えを多数のファイルに入れるときに、編集の衝突を避けて並べられます。

共有用

Claude Code の `/batch` を使うと、大きな機械的変更を 5〜30 個の worktree 分離サブエージェントに分けて進められます。ファイル同士が衝突しないので、同じ置き換えを多数のファイルに入れる作業に向いています。https://code.claude.com/docs/en/agents

👥 チームTips

MCP：ツールを「読む＝許可、書く／外に送る＝確認、壊す＝拒否」で分け、既定は確認にする

DigitalOcean の MCP セキュリティ解説は、読み取り専用の呼び出しだけを許可し、書き込みや社外への送信は確認、破壊的な操作は拒否、新しいツールの既定は確認か拒否にするよう勧めています。自動承認は最後の砦をなくします。

共有用

MCP のツールは「読むだけは許可、書き込みや外部送信は確認、破壊的な操作は拒否」に分け、新しいツールの既定は確認にしておくと、誤作動や注入されたときの被害を抑えられます。https://www.digitalocean.com/resources/articles/mcp-security
