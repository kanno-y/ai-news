👥 チームTips

Claude Code チームのレビュー手順を真似する：検証させる→別の目でレビュー→3周で打ち止め

エージェントにはテストやビルドなど実行できる確認手段を渡し、「できました」ではなく実行結果を見せてもらいます。そのうえで、文脈を引き継がないサブエージェントに差分をレビューさせます。PR を出す前に手元で /code-review と /security-review を流し、何度も出るレビュー指摘は REVIEW.md にまとめておきます。エージェント同士のレビュー合戦が延々と続かないよう、レビューは3周までにします。

共有用

Claude Code チームのレビュー手順が参考になりそうです。PR 前にエージェントにテスト結果を見せてもらい、別のサブエージェントでレビューし、手元で /code-review と /security-review を流す、指摘はREVIEW.mdにまとめ、レビューは3周まで、という流れです。 https://claude.dev/blog/solving-code-review-at-anthropic/

👥 チームTips

ルールを AGENTS.md 1つにまとめて Cursor と Claude Code で共有する

Cursor はルートと下位フォルダの AGENTS.md を読みます。Claude Code は、プロジェクトに CLAUDE.md がなければ AGENTS.md をそのまま読みます。CLAUDE.md がある場合は、先頭に @AGENTS.md と書けば取り込めます。ハマりどころが2つあります。.cursor/rules に置くファイルは .mdc でないと無視されること、CLAUDE.local.md を置くと Claude Code が AGENTS.md を読まなくなることです。

共有用

Cursor と Claude Code のルールは AGENTS.md 1つにまとめられます。CLAUDE.md がある場合は先頭に @AGENTS.md と書けば取り込めます。注意点として、.cursor/rules に置くファイルは拡張子が .mdc でないと無視されます。 https://code.claude.com/docs/en/memory / https://cursor.com/docs/context/rules

👥 チームTips

CLAUDE.md は200行以内にし、フォルダ別の指示は .claude/rules/ の paths で分ける

公式は CLAUDE.md を200行以内に収めることを推奨しています。一部のコードにしか関係ない指示は、.claude/rules/ の中に frontmatter で paths:（例："infra/**/*.ts"）を付けたファイルとして置くと、該当ファイルを触ったときだけ読み込まれます。/doctor prompt-audit を実行すると、古い指示や矛盾する指示を探してくれます。毎回必ず実行させたいこと（コミット前の lint など）は CLAUDE.md に書くより hook にするのが確実です。

共有用

CLAUDE.md は200行以内が推奨だそうです。IaC やフロントなど一部にしか関係ない指示は .claude/rules/ に paths: 付きで分けると、該当ファイルを触ったときだけ読み込まれます。/doctor prompt-audit で古い指示や矛盾も探せます。 https://code.claude.com/docs/en/memory
