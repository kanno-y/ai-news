Aurora Serverless が最大 384 ACU に（Aurora PostgreSQL）

Aurora PostgreSQL の Serverless の上限が 384 ACU になり、Platform Version 4 の既存クラスターは最大容量を変えるだけでダウンタイムなしに使えます（PostgreSQL 18.4 / 17.10 / 16.14 / 15.18 / 14.23 が対象）。

Claude Code：/verify に起動手順を覚えさせる

/run-skill-generator を一度実行すると、アプリの起動手順が .claude/skills/ にプロジェクトのスキルとして記録され、/run と /verify がそれに従って変更を実際に動かして確認します。プロジェクトに verify スキルがあると、v2.1.286 以降はコミット直前にも実行されます。

共有用

Claude Code で /run-skill-generator を一度実行すると、アプリの起動手順がプロジェクトのスキルとして記録され、/verify がそれを使って変更を実際に動かして確認してくれます。verify スキルがあるとコミット前にも実行されるので、リポジトリにコミットしておくのがおすすめです。 https://code.claude.com/docs/en/slash-commands

Grok Build：ワークツリーでも「常に許可」を引き継ぐ

Grok Build 1.0.67 から、ワークツリーはメインのチェックアウトで「常に許可」した答えを使うので、同じツールの確認が繰り返されません。オフにするなら [features] worktree_inherits_main_approvals = false。「許可しない」はどちらの場合も効きます。

共有用

Grok Build（1.0.67〜）では、ワークツリーがメインのチェックアウトで「常に許可」した設定を引き継ぐので、並列作業で同じ確認に何度も答える必要がなくなりました。引き継ぎたくない場合は config の [features] worktree_inherits_main_approvals = false で止められます。 https://x.ai/changelog/build

AgentCore Gateway：モデルが絞られても止まらないフォールバック

AgentCore Gateway のルールで matchModels と routeToTarget を指定し、fallback に代替先（1〜2個）と triggerOn の条件、firstByteTimeoutMilliseconds を設定できます。ストリーミングが始まった後は切り替わらない点に注意です。

共有用

Amazon Bedrock AgentCore Gateway では、ルールにモデルのフォールバック先を最大2つ指定でき、スロットリングや最初の応答の遅れをきっかけに自動で別のモデルへ切り替えられます。エージェントを本番で動かすときの保険として設定しておくと安心です。 https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-rules-fallback.html

Vercel：5xx の比率をカスタムモニターで見張る

Observability のクエリからモニターを作り、「エラー数 ÷ 総リクエスト」のような比率や異常検知でアラートを出せます。vercel monitors schema --type custom でスキーマを確認し、JSON から vercel monitors add で作成できます（Pro / Enterprise と Observability Plus が必要）。

共有用

Vercel のカスタムモニターで、5xx エラーの比率などを閾値や異常検知で監視できるようになりました。JSON で定義して vercel monitors add で作れるので、監視設定をコードとして管理できます（Observability Plus が必要）。 https://vercel.com/changelog/create-custom-monitors-in-vercel-observability
